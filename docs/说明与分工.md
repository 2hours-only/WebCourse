# 一、功能与界面效果目标

整个系统的流程目标如下：

```
用户输入需求
    ↓
系统智能推荐
    ↓
用户选择座位
    ↓
生成订单
    ↓
完成购票
```

不要设计很多页面，围绕上面的"快速选座"流程设计即可，作业要求**Don't Make Me Think.**

页面采用如下布局：

```
┌──────────────────────────────────────────────────────┐
│ Header                                               │
├──────────────┬──────────────────────┬────────────────┤
│              │                      │                │
│  左侧控制区    │      座位图          │   右侧信息区域   │
│              │                      │                │
├──────────────┴──────────────────────┴────────────────┤
│ Footer                                               │
└──────────────────────────────────────────────────────┘
```

具体的：

左侧：

- 用户信息输入
- 推荐按钮
- 无障碍设置

中间：

- Canvas影院
- 座位交互
- 热力图显示

右侧：

- 推荐信息
- 当前选座
- 订单信息
- 购票操作

# 二、整体架构与对象模型

系统架构分层，各层职责单一, 方便大家各自独立推进。

```
UI层
↓
交互层
↓
业务逻辑层
↓
推荐算法层
↓
Canvas渲染层
↓
数据层
↓
LocalStorage存储
```

### 整个系统由 main.js 负责调用，其余层彼此之间-不允许-相互调用!!! (>ᴗ<)

正确流程：

```
main
    │
    ├── recommend
    ├── canvas
    ├── storage
    └── ui
    ...
```

错误流程：

```
recommend
↓
canvas
↓
canvas
↓
storage
↓
storage
↓
ui
```

---

整个项目包含四种核心对象。

## Cinema

表示整个影院。

包含：

- 行数
- 列数
- 屏幕位置
- 所有座位

Canvas绘制影院时读取Cinema。
推荐算法也读取Cinema。

## Seat

表示一个座位。

包含：

- 行号
- 列号
- 当前状态（空闲/已售/已选）
- 是否推荐
- 热度
- 评分
- 价格

**Seat全局唯一**, Canvas、推荐、订单全部操作同一个Seat对象，**不允许复制数据**。

## UserPreference

表示用户输入。

包含：

- 年龄
- 人数
- 观影类型
- 是否开启无障碍模式
- （可扩展预算等）

推荐算法只读取UserPreference。

## Order

表示订单。

包含：

- 订单编号
- 座位列表
- 金额
- 时间
- 状态

LocalStorage最终保存Order。

## app

整个项目入口。

负责：

- 初始化项目
- 初始化数据
- 注册事件
- 协调各模块工作

不负责任何具体业务逻辑。

#### app/main.js

整个系统的控制中心，只做流程调度。

**负责**

- 初始化 Cinema（从 data 读取）

- 初始化 UI

- 绑定事件监听

- 调用 recommend 获取推荐结果

- 调用 canvas 更新画面

- 调用 storage 保存订单

- 协调所有模块数据流

**禁止**

- 写推荐算法

- 写Canvas绘制逻辑

- 写UI组件细节

- 直接操作LocalStorage

## core

对象模型定义。

- 影院Cinema
- 座位Seat
- 订单Order

#### core/cinema.js

定义影院结构Cinema。

**负责**

- 创建影院结构
- 初始化行列信息
- 管理座位矩阵
- 提供基础查询接口（如获取某一行座位）

**禁止**

- 涉及UI
- 涉及推荐逻辑
- 直接渲染Canvas

#### core/seat.js

定义座位对象结构Seat, 且**全局唯一**。

**包含字段**

- row / col
- status（空闲 / 已售 / 已选）
- heat（热度）
- score（评分）
- isRecommended（是否推荐）
- price

**禁止**

- 修改UI
- 计算推荐
- 保存数据

#### core/order.js

定义订单对象结构Order。

**负责**

- 订单对象生成规则
- 订单字段定义
- 状态管理（已购 / 已取消）

**禁止**

- 操作Seat
- 直接存储（应当storage负责）

## canvas

电影院Canvas绘制。

包括：

- 绘制银幕
- 绘制座位
- 绘制文字
- 绘制热力图
- 点击交互
- Hover效果
- 拖拽（加分项）

只画，不负责推荐算法，不负责订单。

#### canvas/renderer.js

画一切可见内容。

**接受输入**：

- Cinema
- Seat列表

**负责**

- 影院屏幕绘制
- 座位绘制
- 座位状态颜色（空闲/选中/已售/推荐）
- 文字渲染

**禁止**

- 做推荐
- 处理点击逻辑（interaction负责）
- 操作数据存储

#### canvas/interaction.js

处理Canvas上的用户交互。

**负责**

包括：

- 点击座位
- 多选座位
- hover反馈
- 拖拽选座（加分项）
- 输出“用户选中了哪个Seat”的事件

**禁止**

- 画图
- 计算推荐
- 存储数据

#### canvas/heatmap.js

生成和绘制热力图。

**负责**

- 座位热度计算展示
- 区域热度颜色映射（红/黄/绿）
- 热门区域提示(热度数据来源于 Seat.heat)

## recommend

负责智能推荐。

包括：

- 推荐算法
- 推荐规则
- 评分计算
- 推荐理由

推荐算法最终输出推荐座位列表, 交由Canvas显示。

#### recommend/recommend.js

智能推荐入口函数。

**负责**

- 接收 UserPreference + Cinema

- 调用 rule + score

- 输出推荐座位列表

**输出**

- [Seat, Seat, Seat]

**禁止**

- 操作Canvas

- 修改UI

- 保存订单

#### recommend/rule.js

定义“规则层”,也就是各种条件判断。

- 青少年避开前排

- 老人避开后排

- 情侣推荐中间双座

- 团体推荐连续座位

#### recommend/score.js

**负责**

给每个Seat打分。

评分维度：

- 视角

- 距离

- 舒适度

- 周围空位

**输出**

- seat.score = 0 ~ 100

## utils

公共工具。

例如：

- 数学函数
- 配置
- 常量
- 通用工具函数

所有模块都可以调用。

#### utils/config.js

全局配置文件

**负责**

- 座位大小

- Canvas尺寸

- 颜色配置

- 推荐权重参数

- ......

#### utils/math.js

通用数学工具

**负责**

- 距离计算

- 权重计算

- 坐标转换
- ......

#### utils/eventBus.js

降低 main.js 的复杂度，避免其充斥大量回调函数, 负责模块间的解耦通信。

**负责**

- 提供全局事件监听 (`on`)
- 提供全局事件触发 (`emit`)
- 实现 UI层、Canvas层、业务逻辑层之间的消息传递

**使用规范**

- UI层：监听用户操作，emit `user-input-change` 等事件。
- Canvas层：监听画布点击，emit `seat-click` 事件。
- Main层：on 监听上述事件，调用业务逻辑，再调用其他层更新。

**禁止**

- 业务逻辑层（Recommend/Order）直接使用 EventBus，它们应保持纯函数特性，由 Main 调用。

# 四、分工

#### ① 整体部分（组长）

- 项目框架
- 页面骨架
- 数据模型
- main.js协调
- Git维护
- 最终联调

| 负责文件                    | 具体内容                                                             |
| :-------------------------- | :------------------------------------------------------------------- |
| **`js/app/main.js`**        | 核心调度中心。初始化所有模块、监听 EventBus、协调数据流向。          |
| **`js/core/`**              | 数据模型定义。                                                       |
| **`js/data/cinemaData.js`** | 定义影院的行列数、初始已售座位、默认热度分布。                       |
| **`js/utils/config.js`**    | 全局配置。座位大小、Canvas尺寸、颜色主题变量、推荐算法的权重参数等。 |
| **`js/utils/eventBus.js`**  | 基础设施。提供事件监听与触发机制。                                   |
| **`js/utils/math.js`**      | 通用工具。提供坐标转换、距离计算等工具函数。                         |
| **`index.html`**            | 页面骨架。编写 HTML 结构，划分 Left/Center/Right 区域。              |
| **`css/layout.css`**        | 页面布局。编写 Flex 布局、响应式大体框架。                           |

---

#### ② Canvas部分

- 影院绘制
- 点击交互
- 拖拽
- 热力图

> 只负责“画”和“发事件”，**不要**修改 Seat 的数据，**不要**写推荐逻辑。

| 负责文件                       | 具体内容                                                                                                               |
| :----------------------------- | :--------------------------------------------------------------------------------------------------------------------- |
| **`js/canvas/renderer.js`**    | 渲染核心。负责绘制银幕、遍历 `Cinema` 对象绘制所有座位、根据 `Seat.status` 映射颜色、绘制推荐标记。                    |
| **`js/canvas/interaction.js`** | 交互捕捉。监听 Canvas 的 click/mousemove 事件，计算点击坐标对应的 `Seat` 对象，触发 `onSeatClick` 回调。实现拖拽选座。 |
| **`js/canvas/heatmap.js`**     | 热力图。读取 `Seat.heat` 数据，绘制红/黄/绿叠加层。                                                                    |

---

#### ③ 推荐算法部分

- 推荐规则
- 评分系统
- 推荐理由

> 只负责“算”，**不要**操作 Canvas，**不要**直接修改 UI。

| 负责文件                        | 具体内容                                                                               |
| :------------------------------ | :------------------------------------------------------------------------------------- |
| **`js/recommend/recommend.js`** | 入口逻辑。接收 `UserPreference` 和 `Cinema`，调用规则和评分，返回推荐座位列表。        |
| **`js/recommend/rule.js`**      | 规则层。编写硬性过滤规则（如：青少年避开前三排、情侣找连座、老人避开后排）。           |
| **`js/recommend/score.js`**     | 评分层。编写软性评分逻辑（视角权重、距离权重、舒适度计算），最终给 Seat 打分 (0-100)。 |
